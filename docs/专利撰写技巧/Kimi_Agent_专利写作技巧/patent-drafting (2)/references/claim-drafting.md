## 1. 权利要求的基本结构

每项权利要求是一个单句，结构如下：

```
[preamble 前序部分] + [transitional phrase 过渡短语] + [body 主体部分]
```

### 1.1 前序部分 (Preamble)
- 定义发明主题名称和类别
- 示例: "一种[用于XXX的]装置/方法/系统"
- 包含与最接近现有技术共有的必要技术特征（划界用途）

### 1.2 过渡短语 (Transitional Phrase)
| 短语 | 含义 | 保护范围 | 使用场景 |
|------|------|----------|----------|
| **comprising/包括/包含** | 开放式，允许额外元素 | 最宽 | 默认首选 |
| consisting of/由...组成 | 封闭式，仅限所列元素 | 窄 | 化学组合物 |
| consisting essentially of/基本上由...组成 | 半开放，允许不显著改变的元素 | 中等 | 化学领域 |

### 1.3 主体部分 (Body)
- 列出发明的技术特征和限定
- 独立权利要求：区别特征用"其特征在于..."
- 用分号分隔各特征，倒数第二项用"; and"或";以及"

## 2. 独立权利要求撰写

### 2.1 两段式写法（中国专利）

```
一种[主题名称]，包括/包含[共有技术特征]，
其特征在于，[区别技术特征]。
```

### 2.2 撰写原则
- **必要性原则**：只包含解决技术问题的必要技术特征
- **最大保护范围**：在具备新颖性、创造性的前提下，范围尽可能宽
- **避免多余限定**：不包含可有可无的特征
- **一个独立权利要求应尽量涵盖所有实施方式**

### 2.3 必要技术特征的确定
1. 明确发明解决的技术问题
2. 确定为解决该技术问题所不可或缺的技术特征
3. 删除不影响解决技术问题的 ornamental 特征

### 2.4 独立权利要求模板

**产品/装置类：**
```
一种[主题名称]，包括：
  第一模块，配置用于[功能A]；
  第二模块，与所述第一模块通信，配置用于[功能B]；
  处理单元，操作连接至所述第二模块，配置用于[功能C]；以及
  输出接口，连接至所述处理单元，配置用于[功能D]。
```

**方法类：**
```
一种[主题名称]的方法，包括：
  步骤A：[描述]，
  步骤B：[描述]，
  步骤C：[描述]，以及
  步骤D：[描述]。
```

**系统类：**
```
一种[主题名称]的系统，所述系统包括：
  采集端，配置用于[数据采集任务]；
  服务端，通信连接至所述采集端，配置用于[数据处理任务]；
  客户端，通信连接至所述服务端，配置用于[结果展示任务]。
```

## 3. 从属权利要求撰写

### 3.1 结构
```
[引用部分] + [限定部分]
```

- **引用部分**："根据权利要求X所述的[主题名称]，..."
- **限定部分**：附加技术特征

### 3.2 引用关系形式

**直线式**（Chain）：
```
权2引用权1 → 权3引用权2 → 权4引用权3
```

**放射式**（Radial）：
```
权2引用权1
权3引用权1
权4引用权1
```

**混合式**（Combined）：实际中最常用

### 3.3 中国专利特殊规则
- **允许多项从属权利要求**（择一引用）
- **禁止多级多项从属**：多项从属权利要求不得被另一项多项从属权利要求引用
- **示例**："根据权利要求1或2所述的..." ✓
- **禁止**："根据权利要求1、2或3所述的...后又作为多项被引用" ✗

### 3.4 从属权利要求的战略作用
1. **Fallback positions**：审查中可合并入独立权利要求
2. **层次化保护**：从宽到窄的多层次保护网
3. **具体化实施方式**：连接上位概念与具体实施例
4. **防规避设计**：覆盖替代方案

## 4. 权利要求类型

### 4.1 按性质划分
| 类型 | 说明 | 示例 |
|------|------|------|
| **物的权利要求** | 产品、装置、系统 | "一种智能温控系统..." |
| **活动的权利要求** | 方法、工艺、用途 | "一种数据处理方法..." |

### 4.2 按形式划分
| 类型 | 保护对象 |
|------|----------|
| **独立权利要求** | 完整技术方案，最宽保护范围 |
| **从属权利要求** | 对引用的权利要求进一步限定 |

### 4.3 组合建议
- 重要发明应同时包含：产品权利要求 + 方法权利要求
- 软件专利：系统权利要求 + 方法权利要求 + 存储介质权利要求
- 化学发明：化合物权利要求 + 制备方法权利要求 + 用途权利要求

## 5. 撰写步骤

### Step 1: 理解发明
- 通读技术交底书，理解技术方案全貌
- 识别：技术问题 → 技术方案 → 技术效果
- 找出与现有技术的区别点（新颖性所在）

### Step 2: 确定最接近现有技术
- 检索或根据交底书中提供的背景技术
- 确定共有特征和区别特征

### Step 3: 撰写独立权利要求
1. 确定主题名称
2. 将共有特征写入前序部分
3. 将区别特征写入特征部分（"其特征在于..."）
4. 检查是否只包含必要技术特征
5. 确认范围不过宽（会被驳回）也不过窄（易被规避）

### Step 4: 规划从属权利要求布局
1. 确定需要进一步限定的特征
2. 设计层次结构（哪些是对独立权利要求的直接限定，哪些是间接限定）
3. 确保从属权利要求之间有实质性区别
4. 建议数量：独立1项 + 从属3-10项

### Step 5: 检查和优化
- 使用自检清单（见第7节）
- 确保术语一致
- 验证引用关系

## 6. 常见错误与避免

### 6.1 语法错误
| 错误 | 正确 | 说明 |
|------|------|------|
| 多个句号 | 仅结尾一个句号 | 权利要求是单句 |
| "the"先于"a/an" | 首次出现用"a/an" | Antecedent basis |
| "the element"未引入 | 先用"an element" | 指代基础 |
| 含义不确定词汇 | 精确术语 | "约""等""最好是" |

### 6.2 实质性错误
- **保护范围过宽**：缺乏新颖性/创造性支持
- **保护范围过窄**：易被竞争对手规避
- **功能性限定过多**：缩小保护范围
- **缺少替代方案**：未在从属权利要求中布局
- **主题不清楚**：产品/方法混淆

### 6.3 结构错误
- 从属权利要求引入新主题名称
- 多项从属引用多项从属（中国禁止）
- 权利要求编号不连续
- 两项以上保护范围实质相同的权利要求

## 7. 权利要求自检清单

### 格式检查
- [ ] 每项权利要求是单句，仅一个句号在末尾
- [ ] 编号连续，阿拉伯数字
- [ ] 从属权利要求排在独立权利要求之后
- [ ] 无插图，附图标记在括号中
- [ ] 无商业性宣传用语

### 内容检查
- [ ] 术语与说明书一致
- [ ] 首次出现的元件用"a/an"，之后用"the/said"
- [ ] 类型清楚（产品/方法不混淆）
- [ ] 保护范围清楚（无模糊词汇）
- [ ] 引用关系清楚且合规
- [ ] 独立权利要求仅含必要技术特征
- [ ] 从属权利要求有实质性区别
- [ ] 满足单一性要求
- [ ] 以说明书为依据

### 战略检查
- [ ] 独立权利要求范围适当（不宽不窄）
- [ ] 从属权利要求形成层次化保护
- [ ] 包含替代方案的从属权利要求
- [ ] 重要发明同时有产品和方法权利要求
