## 1. 说明书整体结构

中国发明专利/实用新型说明书标准结构：

```
发明名称
技术领域
背景技术
发明内容
  ├── 要解决的技术问题
  ├── 技术方案
  └── 有益效果
附图说明
具体实施方式
说明书摘要
摘要附图
```

### 撰写核心原则
- **充分公开**：所属领域技术人员能够实现（enablement）
- **支持权利要求**：每一项权利要求特征在说明书中找到依据
- **公开换保护**：公开充分换取保护范围
- **术语统一**：全文术语一致，前后无矛盾

## 2. 发明名称

### 要求
- 不超过25个字
- 反映主题和类型（装置/方法/系统）
- 不使用：人名、地名、商标、型号、商品名称、商业宣传用语
- 不含"技术"（如已明确类型则不必）

### 示例
- "一种基于深度学习的图像识别方法及系统"
- "一种智能温控阀门装置"
- "一种用于废气处理的催化反应器"

---

## 3. 技术领域

### 写法
指明发明直接所属或直接应用的具体技术领域。

### 要求
- 不是上位领域（如"本发明属于电子领域"太宽）
- 不是发明本身（如"本发明是一种智能手表"不对）
- 用"本发明涉及..."开头

### 示例
```
本发明涉及计算机视觉技术领域，尤其涉及一种基于多尺度特征融合的目标检测方法。
```

## 4. 背景技术

### 内容
1. 简述现有技术的结构和原理
2. 客观指出现有技术的不足（技术问题）
3. 引证相关专利或文献（如有）

### 要求
- 客观、具体，不贬低现有技术
- 明确"现有技术存在以下问题：..."
- 引证文件要求：公开出版物，非专利文件公开日应在本申请申请日之前
- 1-3段为宜

### 撰写模板
```
现有技术中，[描述现有方案A]，然而，[方案A的问题1]，
[方案A的问题2]。

进一步的，[描述现有方案B]，[方案B的问题]。

因此，如何[技术需求]，成为亟待解决的技术问题。
```

## 5. 发明/实用新型内容

### 5.1 要解决的技术问题
- 针对背景技术中的不足，正面明确说明
- 1-3个技术问题，按重要性排列
- 避免笼统提法：如"提高效率"应改为"如何提高XX处理效率"

### 5.2 技术方案
- 至少包含独立权利要求的完整技术方案
- 用"本发明提供一种..."开头
- 描述清楚、完整，使技术人员能实现
- 与权利要求表述一致

### 5.3 有益效果
- 对照现有技术，具体描述优点
- 效果应与技术问题对应
- 尽量有数据支撑（如"准确率提升15%"）
- 分析效果产生的原因（不是简单列举）

### 撰写模板
```
本发明提供一种[主题名称]，以解决现有技术中[问题描述]的问题。

为实现上述目的，本发明采用如下技术方案：

一种[主题名称]，包括[特征A]、[特征B]，所述[特征A]配置用于
[功能]，所述[特征B]与所述[特征A]连接，配置用于[功能]。

进一步的，所述[特征]还包括[细节]。

本发明实施例提供的技术方案，通过[技术手段]，解决了[技术问题]，
达到了[有益效果]。与现有技术相比，本发明具有以下有益效果：
（1）[效果1]，原因在于[分析]；
（2）[效果2]，经测试[数据支持]；
（3）[效果3]。
```

## 6. 附图说明

### 内容
- 列出所有附图，说明每幅图的名称和内容
- 标注图中主要部件的引用编号
- 示例："图1为本发明实施例的系统架构图；"

### 要求
- 实用新型必须有附图
- 发明如有附图应清晰表达发明内容
- 同一部件在不同视图中用同一编号
- 附图中不应出现汉字（必要时用标号代替）

## 7. 具体实施方式

### 7.1 作用
- 说明书最长、最核心的部分
- 支持权利要求的依据
- 判断公开充分的关键

### 7.2 撰写要求
1. **结合实施例描述**：至少一个，通常多个
2. **详略得当**：核心发明点详细，公知技术简略
3. **配合附图**：引用附图编号说明
4. **参数具体**：涉及数值范围给出端值示例
5. **替代方案**：列出可想到的变型方案

### 7.3 实施例数量
| 情况 | 建议数量 |
|------|----------|
| 技术方案简单，一个实施例足以支持 | 1个 |
| 权利要求覆盖范围较宽 | 2个以上 |
| 涉及数值范围 | 两端值+中间值 |
| 有多种并列实施方式 | 每种至少1个 |

### 7.4 实施例撰写模板

**实施例1（优选实施例）：**
```
为使本发明的目的、技术方案和优点更加清楚，下面将结合附图对本发明
作进一步地详细描述。

参见图1，本发明实施例提供一种[主题名称]，包括：

[组件A] 100，配置用于[功能描述]。在本实施例中，[组件A]
采用[具体实现]，其参数为[具体数值]。

[组件B] 200，通信连接至所述[组件A] 100。[组件B]包括
[子组件]和[子组件]，用于[功能描述]。

工作时，[描述工作流程，从输入到输出的完整过程]。
具体地，步骤如下：
步骤1：[详细描述]，其中[参数]设置为[值]；
步骤2：[详细描述]；
步骤3：[详细描述]，得到[结果]。

实验结果表明，[具体数据]，相比现有技术[对比数据]，
[效果提升]。
```

**实施例2（替代实施例）：**
```
实施例2与实施例1的区别在于[区别点]。
在本实施例中，[组件A]替换为[替代方案]，采用[不同实现]。
其余结构与实施例1相同，不再赘述。

本实施例同样实现了[效果]，适用于[不同应用场景]。
```

### 7.5 扩展保护范围的技巧
- 实施例覆盖权利要求的上位概念
- 提供多种替代方案，防止竞争对手规避
- 数值范围给出端值和中间值的实施例
- 结构变型、材料替代、工艺参数变化等

## 8. 说明书摘要

### 要求
- 300字以内
- 包含：名称、技术领域、技术问题、方案要点、主要用途
- 以独立权利要求的技术方案为主
- 不用于解释权利要求
- 有附图时需指定摘要附图

### 示例
```
本发明公开了一种基于区块链的数据存证方法，属于信息安全技术领域。
该方法包括：接收待存证数据；计算所述数据的哈希值；将所述哈希值及
时间戳写入区块链；返回存证凭证。本发明解决了传统数据存证易篡改、
难追溯的问题，提高了数据可信度和可追溯性。
```

## 9. 说明书自检清单

### 格式检查
- [ ] 发明名称≤25字，无商标/人名/宣传用语
- [ ] 各部分顺序正确
- [ ] 术语全文一致
- [ ] 附图编号连续，与文字对应

### 内容检查
- [ ] 技术领域描述准确（不宽不窄）
- [ ] 背景技术客观，问题描述清楚
- [ ] 技术问题与背景技术对应
- [ ] 技术方案至少包含独立权利要求的全部特征
- [ ] 有益效果具体，有分析或数据
- [ ] 具体实施方式详细到技术人员可实现
- [ ] 实施例支持权利要求的保护范围
- [ ] 替代方案/变型方案已描述
- [ ] 摘要≤300字

### 一致性检查
- [ ] 说明书中的术语与权利要求书一致
- [ ] 附图标记与说明书文字一致
- [ ] 技术方案描述与权利要求对应
- [ ] 背景技术中的问题与技术问题对应
- [ ] 效果描述与技术方案对应
